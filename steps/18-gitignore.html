STEP 18

.gitignore で「無視する」ファイルを指定する

このステップのゴール

  • Git に管理させたくないファイルを除外できるようになる
  • .gitignore の書き方を覚える

なぜ「無視する」設定が必要？

プロジェクトを作っていると、リポジトリに 含めたくないファイル が必ず出てきます。

  • パスワードや API キーが入った設定ファイル (.env など)
  • ビルドの中間生成物 (node_modules/, dist/, build/ など)
  • OS が勝手に作るファイル (.DS_Store, Thumbs.db)
  • エディタの設定フォルダ (.vscode/ の一部, .idea/ など)

これらをコミットしてしまうと、リポジトリが重くなったり、 最悪パスワードを世界中に公開してしまうことになります。.gitignore はそれを防ぎます。

.gitignore を作る

リポジトリの一番上に、.gitignore という名前のファイルを作るだけ。中身に「無視したいファイルやフォルダの名前」を1行ずつ書きます。

例: シンプルな .gitignore

# OS が作る邪魔なファイル
.DS_Store
Thumbs.db

# パスワードや API キー
.env

# ログファイル
*.log

# ビルド成果物
node_modules/
dist/
build/

# から始まる行はコメントです。Git は無視するので、自分用のメモとして使えます。

書き方のルール

書き方 意味
secret.txtこの名前のファイルを無視 (どの階層でも)
*.log.log で終わるすべてのファイル
build/build という名前のフォルダ全体
/secret.txtリポジトリ直下の secret.txt だけ (深い階層は対象外)
!important.log無視リストから除外 (例外的に管理対象にする)

テンプレートを使う

自分でゼロから書かなくても、よく使われる .gitignore のテンプレートが GitHub に用意されています。

  • github.com/github/gitignore — 公式のテンプレート集
  • gitignore.io — 言語/ツール名を入れると、最適な内容を自動生成してくれるサービス
たとえば「Node.js + macOS + VS Code」と指定すれば、それらに最適化された .gitignore がワンクリックで生成できます。

動作を確認する

.gitignore をリポジトリの直下に置いた後、無視されるはずのファイルを作ってみましょう。 

echo "secret password" > .env
git status

.env が表示されなければ、無視がきちんと効いています。

すでにコミット済みのファイルは、後から .gitignore に追加しても無視されません。 その場合は、まず git rm --cached <ファイル名> でリポジトリから削除してから、コミットし直す必要があります。

.gitignore も忘れずにコミット

.gitignore 自体はリポジトリで管理するファイルです。作ったらコミットしましょう。 

git add .gitignore
git commit -m ".gitignore を追加"
git push

このステップのまとめ

  • リポジトリ直下の .gitignore に「無視するファイル名」を書く
  • パスワード・ビルド成果物・OS のゴミファイルを必ず除外する
  • テンプレートを使えば自分で書く必要なし
  • コミット済みファイルは後から無視できない ので注意
