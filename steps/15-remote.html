STEP 15

ローカルとリモートを連携させる

このステップのゴール

  • 「ローカル」と「リモート」の関係を理解する
  • パソコン上のリポジトリと GitHub のリポジトリを紐付ける

ローカルとリモート

ここまで作業してきたパソコン上のリポジトリを 「ローカルリポジトリ」 と呼びます。 対して、GitHub に置いてあるリポジトリを リモートリポジトリ と呼びます。 

あなたのPC                          GitHub
┌─────────────────┐                  ┌─────────────────┐
│ ローカル         │ ←── 連携 ──→     │ リモート         │
│ リポジトリ       │                  │ リポジトリ       │
└─────────────────┘                  └─────────────────┘

この2つを連携させると、変更を双方向にやり取りできる ようになります。 その「やり取り」が次のステップの プッシュ と プル です。

連携のしかた

連携のしかたは、状況によって少し違います。

  • ローカルにすでにリポジトリがある場合 (今回のケース) → リモートを追加する
  • GitHub のリポジトリを新たに自分のPCに持ってくる → クローン (STEP 17) を使う

リモートを追加する

① GitHub のリポジトリ URL をコピー

STEP 14 で開いておいた GitHub のリポジトリ画面で、URL をコピーします。 画面中央の「Quick setup」の右側に表示されているはずです。 

https://github.com/<ユーザー名>/my-first-repo.git

② リモートを追加するコマンドを実行

ターミナルで、ローカルリポジトリのフォルダにいる状態で:

git remote add origin https://github.com/<ユーザー名>/my-first-repo.git

この origin は、リモートに付ける「呼び名」です。origin はリモート1つ目のお決まりの名前として広く使われています。

③ 連携できたか確認

git remote -v

こんな表示が出れば成功です。

origin  https://github.com/<ユーザー名>/my-first-repo.git (fetch)
origin  https://github.com/<ユーザー名>/my-first-repo.git (push)

GitHub Desktop でリモートを公開する

GitHub Desktop で先に my-first-repo を開いてある状態で:

  1. 画面上部の「Publish repository」ボタンをクリック
  2. 「Name」「Description」を確認 (Name は my-first-repo のままで OK)
  3. 「Keep this code private」のチェックは好みに合わせて
  4. 「Publish Repository」を押す

この方法だと、GitHub 上の空リポジトリは Desktop が自動で作ってくれる ので、 STEP 14 で説明した手動作成は実はスキップできてしまいます。

STEP 14 で先に空リポジトリを作ってしまった場合は、上記ではなく次のようにします: 「Repository」メニュー → 「Repository settings...」 → 「Remote」タブで URL を入力。

「origin」って何？

origin は リモートリポジトリの呼び名 (エイリアス) です。 Git でリモートを追加するときの慣例で、最初のリモートには origin という名前をつけることが多いです。

これによって、後々プッシュやプルするとき、長い URL を毎回打たずに origin と書くだけで済むようになります。 

# origin = https://github.com/.../my-first-repo.git の別名
git push origin main

このステップのまとめ

  • ローカル = あなたの PC、リモート = GitHub などサーバ上のリポジトリ
  • git remote add origin <URL> で連携
  • origin はリモートの呼び名 (慣例で「最初のリモート」)
