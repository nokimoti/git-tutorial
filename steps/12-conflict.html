STEP 12

コンフリクト (衝突) を解決する

このステップのゴール

  • コンフリクト がどんな状態かを理解する
  • 落ち着いて手作業で解決できるようになる

コンフリクトはなぜ起きる？

コンフリクト は、同じファイルの同じ場所を、複数のブランチで別々に変更したときに起きます。 Git は「どちらを採用すればいいか自分では判断できない」ので、人間に判断を委ねます。

コンフリクトは 失敗ではなく正常な動作 です。Git があなたに「ここどうしましょう？」と聞いてきている状態だと考えてください。

練習: わざとコンフリクトを起こしてみる

怖がらずに、自分でコンフリクトを起こして解決する練習をしてみましょう。

① 準備: 新しいブランチを作る

git switch main
git switch -c feature

② feature ブランチで hello.txt を変更してコミット

hello.txt の1行目を以下のように書き換えます。

これは feature ブランチの行です。
git add hello.txt
git commit -m "feature ブランチでの変更"

③ main に戻って、同じ1行目を別の内容に書き換えてコミット

git switch main

hello.txt の1行目を以下のように書き換えます。

これは main ブランチの行です。
git add hello.txt
git commit -m "main ブランチでの変更"

④ feature を main にマージしてみる

git merge feature

すると、こんなメッセージが出ます。

Auto-merging hello.txt
CONFLICT (content): Merge conflict in hello.txt
Automatic merge failed; fix conflicts and then commit the result.

これがコンフリクトです。

コンフリクトしたファイルを確認する

hello.txt をエディタで開くと、こんな状態になっています。 

<<<<<<< HEAD
これは main ブランチの行です。
=======
これは feature ブランチの行です。
>>>>>>> feature

記号の意味を読み解くとこうなります。

  • <<<<<<< HEAD から ======= まで → 現在のブランチ (main) の内容
  • ======= から >>>>>>> feature まで → 取り込もうとしているブランチ (feature) の内容

解決のしかた

解決とは、要するに 「どっちを採用するか (または両方を組み合わせるか) を決めて、記号を消す」 ことです。

① エディタで手作業で書き換える

たとえば main の内容を採用するなら、こう書き換えます。

これは main ブランチの行です。

両方を組み合わせたいなら、こうも書けます。

これは main ブランチの行です。
これは feature ブランチの行です。

大事なのは <<< や === や >>> の記号をすべて消す こと。これらの記号は最終的に1つも残ってはいけません。

② 解決済みとして add → commit

git add hello.txt
git commit

コミットメッセージはエディタが起動して自動で入る場合があります。何も書き換えずに保存・閉じれば OK。

VS Code でのコンフリクト解決

VS Code はコンフリクト解決にとても優しいツールです。

  1. コンフリクトしているファイルを開く
  2. 各コンフリクトの上に 「Accept Current Change」「Accept Incoming Change」「Accept Both Changes」「Compare Changes」 というクリック可能なリンクが表示される
  3. 採用したい選択肢をクリック
  4. すべてのコンフリクトを解決したら、ファイルを保存
  5. 左サイドバーの「Source Control」を開き、ステージング (+ ボタン) → コミット

GitHub Desktop でのコンフリクト解決

GitHub Desktop でマージ中にコンフリクトが起きると、ダイアログが出て「VS Code などのエディタで開きますか？」と聞かれます。 エディタで上記の手順で解決し、保存してから戻ってくると、自動でコミット待ち状態になります。 「Continue merge」ボタンを押せば完了です。

マージをやめたいとき

コンフリクト解決中に「やっぱりマージやめたい」と思ったら、こうします。 

git merge --abort

マージ前の状態に戻ります。困ったときの脱出ボタンです。

このステップのまとめ

  • コンフリクトは「人間に判断を委ねる正常な動作」
  • <<< === >>> の記号を消して、採用する内容に整える
  • 整え終わったら git add → git commit
  • やめたいときは git merge --abort
