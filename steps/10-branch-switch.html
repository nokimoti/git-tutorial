STEP 10

ブランチを切り替える

このステップのゴール

  • ブランチ間を行き来できるようになる
  • 切り替え時にファイルの中身が変わることを体感する

ブランチ切り替えの基本

ブランチ 間の移動は、ファイルの中身も一緒に変わる 操作です。 main ブランチで作ったファイルが、experiment ブランチに移動すると違う内容に見える、ということが起こります。 これは混乱しやすいポイントなので、実際に体験してみるのが一番です。

練習: ブランチを切り替えて、違いを見る

STEP 09 で experiment ブランチを作りましたね。 このブランチで hello.txt を変更して、その後 main に戻ってみましょう。

① いまのブランチを確認

git branch

* experiment と表示されていれば OK。

② experiment ブランチで hello.txt を編集

エディタで hello.txt を開いて、こう書き換えます。

これは experiment ブランチでの変更です。

そしてコミットします。

git add hello.txt
git commit -m "experiment ブランチで実験的な変更"

③ main ブランチに戻る

git switch main

切り替えに成功すると、hello.txt の中身が experiment で変更する前の状態に戻っている のが確認できます。

古い書き方では git checkout main ですが、新しい git switch のほうがブランチ切り替え専用なので分かりやすいです。

④ experiment に戻ってみる

git switch experiment

すると、hello.txt はまた「experiment ブランチでの変更」の内容に戻ります。

① ブランチ切り替えメニューを開く

画面上部の「Current branch」と書かれたボタンをクリック。

② 切り替えたいブランチを選ぶ

ブランチ一覧が表示されるので、experiment や main をクリックすれば切り替わります。

切り替えた瞬間、エディタで開いている hello.txt の中身も自動で変わります。

VS Code では 画面左下に現在のブランチ名が表示されています。 そこをクリックすると、即座にブランチ切り替えメニューが開くので便利です。

切り替えできないときの対処

ファイルを編集中で、まだコミットしていない状態で他のブランチに切り替えようとすると、 Git に怒られることがあります。 

error: Your local changes to the following files would be overwritten by checkout

これは「変更が消えてしまうから切り替えできないよ」という警告です。対処は3通り。

  1. コミットする — その変更を残しておきたいなら、まず git commit
  2. 変更を捨てる — いらないなら git restore で消してから切り替え
  3. 一時保存する — git stash で「いったん退避」も可能 (慣れてきたらでOK)

HEAD はブランチと一緒に動く

ブランチを切り替えると、HEAD もそのブランチを指すように動きます。 ブランチが「特定のコミットを指すラベル」、HEAD が「いまどのブランチを見ているかを指すラベル」、と覚えておきましょう。

このステップのまとめ

  • git switch <ブランチ名> で切り替え
  • 切り替えると、ファイルの中身もブランチごとの状態に変わる
  • 未コミットの変更があると切り替えに失敗することがある
