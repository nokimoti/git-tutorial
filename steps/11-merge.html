STEP 11

ブランチをマージする

このステップのゴール

  • あるブランチの変更を、別のブランチに取り込む方法を学ぶ
  • マージ という操作を体験する

マージとは「枝を本流に取り込む」こと

ブランチ で実験的に作業した変更を、main ブランチ に取り込む操作を マージ といいます。 

main:        コミット1 ── コミット2 ──────── マージコミット
                              \            /
experiment:                    変更コミット

この絵のように、experiment で行った変更が main に統合されるイメージです。

マージの手順

実際の手順は意外とシンプルです。「取り込み先のブランチに移動して、取り込みたいブランチをマージする」 これだけです。

例: experiment の変更を main に取り込みたい場合 →

  1. main ブランチに切り替える
  2. experiment をマージするコマンドを実行

① main ブランチに移動

git switch main

② experiment をマージ

git merge experiment

こんな表示が出れば成功です。

Updating 9876abc..f1e2d3c
Fast-forward
 hello.txt | 2 +-
 1 file changed, 1 insertion(+), 1 deletion(-)

main ブランチの hello.txt が、experiment で変更した内容になっているはずです。確認してみてください。

① main ブランチに切り替え

画面上部「Current branch」をクリックして、main を選択。

② マージメニューを開く

  1. もう一度「Current branch」をクリック
  2. 下部の「Choose a branch to merge into main」をクリック
  3. マージしたいブランチ (experiment) を選ぶ
  4. 青い「Create a merge commit」ボタンをクリック

これで experiment ブランチの変更が main に取り込まれます。

2種類のマージ

マージには大きく分けて2種類あり、状況によって自動的に使い分けられます。

① Fast-forward マージ

取り込み先のブランチに 新しい変更がない 場合に使われます。 ブランチを指すラベルを「ぴゅっ」と先に進めるだけ。新しいコミットは作られません。 

main:     A ── B
                \
experiment:      C ── D

↓ マージ後

main:     A ── B ── C ── D
experiment:           ↑

② マージコミット (3-way merge)

取り込み先と取り込み元、両方に変更がある場合は、マージコミット という新しいコミットが作られます。 

main:     A ── B ── E ───── M (マージコミット)
                \           /
experiment:      C ── D ──/

初心者のうちは、これらの違いを意識しなくても大丈夫です。Git が自動でいい感じにやってくれます。

不要になったブランチを消す

マージが終わって役目を果たしたブランチは、削除して構いません。 

git branch -d experiment

-d は「マージ済みなら削除する」、つまり安全な削除です。 もし「マージしてないけど絶対消したい」という場合は -D (大文字) を使います。

GUI では「Branch」メニュー → 「Delete...」から削除できます。

マージで衝突 (コンフリクト) する場合

もし両方のブランチで 同じファイルの同じ箇所 を別々に変更していると、 Git は「どっちを採用すべきかわからない」と止まってしまいます。 これを コンフリクト と呼びます。 次のステップで解決方法を学びます。

このステップのまとめ

  • 取り込み先のブランチに移動 → git merge <取り込み元>
  • マージで2種類の動きがある (Fast-forward / マージコミット)
  • 使い終わったブランチは git branch -d で削除できる
