STEP 01

Gitとは何か

このステップのゴール

  • Git が何をしてくれるツールなのかをイメージできる
  • 「バージョン管理」が何のために必要かを理解する

Git は「ファイルの歴史を残す道具」

Git とは、ファイルの変更履歴を記録・管理できるツールです。 たとえばレポートや作品を作っているとき、こんな経験はありませんか？

  • 「report_最新.docx」「report_最新2.docx」「report_最新_本当に最終.docx」…とファイルが増えていく
  • 昨日まで動いていたコードが、今日はなぜか動かない
  • 誰かが書き換えたコードを元に戻したいけど、どこを変えたのかわからない

Git を使うと、こうした問題はすべて解決できます。Git は「いつ・誰が・どのファイルを・どう変えたか」を、 きれいに記録してくれます。

具体的に何ができる？

  1. 過去のあらゆる時点に戻れる — 1週間前のあの状態に一瞬で復元できる
  2. 変更内容を1行単位で確認できる — どこを足して、どこを消したかが一目瞭然
  3. 複数人で同じファイルを編集できる — 衝突を検出してまとめてくれる
  4. 試したい変更を「枝分かれ」で試せる — 失敗したらすぐ戻れる (これを ブランチ と呼びます)

「リポジトリ」という言葉

Git を使うときに必ず出てくる言葉が リポジトリ です。 リポジトリは「Git が変更履歴を保管する箱」のようなものだと考えてください。 この箱の中には、あなたのファイルと、その変更履歴のすべてが入ります。

「コミット」という言葉

もうひとつよく出てくる言葉が コミット です。 コミットは「変更の保存ポイント」のようなもの。ゲームのセーブポイントだと思ってください。 コミットを残しておくと、いつでもその時点に戻ることができます。

この2つの言葉 (リポジトリ・コミット) は、これからずっと出てきます。 今はぼんやりとしたイメージだけで大丈夫です。手を動かしていくうちに自然と理解できます。

GitHub とは違うの？

よく混同されますが、Git と GitHub は別のものです。

  • Git = あなたのパソコンの中で動く、履歴管理ツール
  • GitHub = インターネット上で Git のリポジトリを共有できる Web サービス

まずは Git だけで十分。GitHub は STEP 14 から触れていきます。

このステップのまとめ

  • Git は変更履歴を管理してくれるツール
  • 履歴は リポジトリ という箱に保管される
  • コミット はセーブポイントのようなもの
