STEP 06

状態を確認する (status と diff)

このステップのゴール

  • 「いま何を変更しているか」を確認できるようになる
  • 変更前後の差分を見られるようになる

なぜ確認が大切？

Git では、何かをする前に 「いまの状態を確認する」 習慣が大切です。 何を ステージング したか、何をまだコミットしていないかを把握しないまま操作すると、 意図しない変更が入ったり、必要な変更が抜けたりするからです。

練習: ファイルを編集してみる

STEP 05 でコミットした hello.txt を、もう一度開いて編集しましょう。 たとえば、こんな1行を追加します。 

はじめての Git のメモ。
今日からバージョン管理を学ぶ。
ステータス確認の練習中。

保存したら、状態を確認してみます。

git status で状態を見る

git status

こんな表示が出ます。

On branch main
Changes not staged for commit:
  (use "git add <file>..." to update what will be committed)
        modified:   hello.txt

no changes added to commit (use "git add" and/or "git commit -a")

読み解くと:

  • On branch main — いま main という ブランチ にいる
  • Changes not staged for commit — 変更はあるが、まだ ステージング されていない
  • modified: hello.txt — hello.txt が変更されている

git diff で何が変わったか見る

git diff

こんな表示が出ます。

diff --git a/hello.txt b/hello.txt
index abc1234..def5678 100644
--- a/hello.txt
+++ b/hello.txt
@@ -1,2 +1,3 @@
 はじめての Git のメモ。
 今日からバージョン管理を学ぶ。
+ステータス確認の練習中。

+ が「追加された行」、- が「削除された行」を表します。 この例では1行追加されたとわかります。

ステージング済みの変更との差分を見たいときは git diff --staged を使います。

GitHub Desktop で状態を見る

GitHub Desktop ではこの操作はとてもシンプルです。 変更があれば、左側のリストに自動的に表示されます。

  1. 左の「Changes」タブを見る
  2. hello.txt がリストに表示される
  3. ファイル名をクリックすると、右側に差分が色付きで表示 される
    • 緑色 = 追加された行
    • 赤色 = 削除された行

コマンドラインでの git status と git diff が、ひとつの画面でまとめて見られる便利な作りです。

3つの状態を意識する

ファイルは Git の中で、3つの状態のいずれかに属しています。

  1. 未追跡 (Untracked) — まだ Git に管理されていない新しいファイル
  2. 変更済み (Modified) — 一度コミット済みだが、その後変更されたファイル
  3. ステージ済み (Staged) — git add されて、次のコミット待ちのファイル

git status はこの3つを色分けして教えてくれます。色分けが見えなくても、文章で 「Untracked files」「Changes not staged」「Changes to be committed」と書いてあるので、慣れれば読めます。

このステップのまとめ

  • 困ったらまず git status
  • 変更内容を見たいときは git diff
  • GUI なら左側のリストに変更が、右側に差分が出る
