STEP 05

ファイルを追加してコミットする

このステップのゴール

  • ファイルを ステージング する
  • はじめての コミット を残す
  • 「add → commit」の流れを身につける

練習用ファイルを作る

STEP 04 で作った my-first-repo フォルダの中に、テキストファイルを1つ作りましょう。 内容は何でも構いませんが、ここでは hello.txt という名前で次のような内容を書いてみます。 

はじめての Git のメモ。
今日からバージョン管理を学ぶ。

2段階で保存する

Git では、変更を保存するときに 2段階 の手順を踏みます。

  1. add — 変更したファイルを ステージング に置く
  2. commit — ステージングにあるものをまとめて リポジトリ に保存する

なぜ2段階なのか？それは、たくさん変更を加えたファイルの中から 「今回はこの変更だけ保存したい」という選択ができるようにするためです。 最初は深く考えずに、「add してから commit するもの」と覚えれば OK です。

add する

ターミナルで、リポジトリのフォルダに移動した状態で次を実行します。

git add hello.txt

これで hello.txt が ステージング に登録されました。 画面には何も表示されませんが、それは正常な動作です。

変更したファイルが複数ある場合、まとめてステージングに入れるには: 
git add .
と実行します。「.」は「現在のフォルダ全部」を意味します。

commit する

続けて、コミットしましょう。

git commit -m "最初のコミット"

-m の後ろのダブルクォートで囲まれた文字列が コミットメッセージ です。 「何を変更したか」を未来の自分が見てわかるように書きます。

成功すると、こんな表示が出ます。

[main (root-commit) abc1234] 最初のコミット
 1 file changed, 2 insertions(+)
 create mode 100644 hello.txt

GitHub Desktop で add & commit

GitHub Desktop を起動してリポジトリを開くと、左側に変更されたファイル一覧が出ます。 hello.txt がリストに表示されているはずです。

  1. 左側のファイル一覧で、コミットしたいファイルにチェックを入れる
    (チェックを入れた状態が「ステージング済み」と同じ意味です)
  2. 左下に「Summary (required)」という入力欄があるので、コミットメッセージを書く
    例: 「最初のコミット」
  3. 下の青いボタン「Commit to main」をクリック

これで完了。GUI ではこのように、add と commit がほぼ一体化した操作になっています。

確認してみよう

コミットが残っているか、次のコマンドで確認できます。

git log

自分の名前と、書いたコミットメッセージが表示されていれば成功です。 この git log コマンドは STEP 07 で詳しく扱います。

コミットメッセージの書き方

コミットメッセージは「未来の自分」に向けて書くものです。コツは次のとおり。

  • 短く要点だけ 書く (50文字以内が目安)
  • 「〜した」より「〜を追加」「〜を修正」のような体言止めが読みやすい
  • 「修正」だけだと意味不明。「ログイン画面のボタン色を修正」など、何をしたかわかるように
練習中は神経質にならず、自分が後で読み返してわかればそれで OK です。

このステップのまとめ

  • 変更を保存する流れ: 編集 → add → commit
  • add は ステージング に置く操作
  • commit は リポジトリ に永続的に保存する操作
  • コミットには「メッセージ」をつけて、何の変更かわかるようにする
