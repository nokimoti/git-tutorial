STEP 13

タグをつける

このステップのゴール

  • タグ が何のためにあるかを理解する
  • リリース版に v1.0.0 のような印をつけられるようになる
  • 軽量タグと注釈付きタグの違いを知る

タグって何？

タグ は 特定のコミットに付ける目印 です。 たとえば「ここがバージョン 1.0.0 の状態」と分かるように、コミットに名札をつけるイメージ。 

main:    A ── B ── C ── D ── E
                  ↑              ↑
                v1.0.0         v1.1.0

長いコミットID (f1e2d3c...) で「あの状態に戻したい」と指定するのは大変ですが、 v1.0.0 のような分かりやすい名前で参照できるようになります。

ブランチとの違い

  • ブランチ は 動く印。新しいコミットを追加すると先端が前に進む
  • タグ は 動かない印。一度つけたらそのコミットに永遠に固定

この性質のおかげで、「リリース時のスナップショット」を残すのにタグはぴったりです。

2種類のタグ

  1. 軽量タグ (lightweight) — ただの名札。コミットへのショートカット
  2. 注釈付きタグ (annotated) — 名前 + 作者 + 日付 + メッセージを持つ正式なタグ
公開・配布するリリースには 注釈付きタグ を使うのが一般的です。 個人的なメモ程度なら軽量タグで十分。迷ったら注釈付きを使っておけば間違いありません。

タグをつける

注釈付きタグ (おすすめ)

git tag -a v1.0.0 -m "最初の正式版"

-a は「annotated」、-m はそのタグに添えるメッセージです。 現在の HEAD (= 直前のコミット) にタグが付きます。

軽量タグ

git tag v1.0.0-light

オプションなしの一行で済みます。

過去のコミットにタグをつける

「このコミットにタグつけたかった!」と後から気づいた場合は、コミットIDを末尾に指定します。

git log --oneline             # コミットIDを確認
git tag -a v0.9.0 9876abc -m "ベータ版"

GitHub Desktop でタグを作る

  1. 上部の「History」タブを開く
  2. タグをつけたいコミットを 右クリック
  3. 「Create Tag...」を選ぶ
  4. タグ名 (例: v1.0.0) を入力 → 「Create Tag」をクリック

コミット行の右側にタグの名札が表示されるようになります。

タグを一覧する

git tag

付いているタグが行ごとに表示されます。

v0.9.0
v1.0.0
v1.0.0-light

条件で絞りたいときは:

git tag -l "v1.*"   # v1 で始まるタグだけ

タグの中身を見る

git show v1.0.0

注釈付きタグなら、タグのメッセージ・作者・日付に加えて、そのコミットの差分まで見られます。

タグの命名ルール (慣例)

自由に名前をつけられますが、世の中のプロジェクトはだいたい セマンティックバージョニング という規則を使っています。 

v[メジャー].[マイナー].[パッチ]
例:  v1.0.0   v1.2.3   v2.0.0-beta.1
  • メジャー — 互換性のない大きな変更
  • マイナー — 後方互換性ありの機能追加
  • パッチ — バグ修正

タグを削除する

git tag -d v1.0.0-light

間違って付けてしまったタグや、不要になったタグを消せます。

タグはリモートには自動で送られない

タグを作っただけでは、ローカルにしか存在しません。 GitHub に送るには 明示的にプッシュ する必要があります。 これは STEP 16: プッシュとプル の知識を踏まえてからでOKですが、書き方だけ: 
git push origin v1.0.0      # タグを1つだけ送る
git push --tags              # 未送信のタグを全部送る

GitHub にタグを送ると、GitHub の「Releases」「Tags」ページに表示され、 他の人がそのバージョンの ZIP を直接ダウンロードできるようになります。

このステップのまとめ

  • タグは 動かない印。リリースのマーキングに最適
  • 注釈付きタグ: git tag -a v1.0.0 -m "メッセージ"
  • 一覧: git tag / 詳細: git show v1.0.0 / 削除: git tag -d
  • リモートに送るには別途 git push --tags
