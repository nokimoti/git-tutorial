STEP 08

変更を取り消す

このステップのゴール

  • 「まだコミットしていない変更」を取り消せるようになる
  • 間違って ステージング したものを取り消せるようになる

取り消しは「いまどの段階か」で方法が変わる

Git の取り消し操作は、「ファイルがどの状態にあるか」 によって変わります。

  1. 編集しただけ (まだ add していない) → ケース A
  2. add した (まだ commit していない) → ケース B
  3. commit までしてしまった → ケース C

順番に見ていきましょう。

ケースA: 編集を取り消したい

hello.txt を編集したけど「やっぱり編集前に戻したい」というケースです。 

git restore hello.txt

これで hello.txt は最後にコミットした状態に戻ります。

この操作は 編集内容を完全に捨てる ため、戻せません。本当に消していいかよく確認しましょう。
  1. 左の「Changes」タブで対象ファイルを右クリック
  2. 「Discard changes」を選ぶ
  3. 確認ダイアログで「Discard Changes」をクリック

これで変更内容が破棄され、最後のコミット時点に戻ります。

ケースB: ステージングだけ取り消したい

git add したけど、「やっぱりこのファイルはコミットに含めたくない」という場合。 編集内容は残したまま、ステージングだけ解除します。 

git restore --staged hello.txt

ファイルの編集内容はそのままで、ステージングからは外れます。

古い書き方では git reset HEAD hello.txt ですが、新しい git restore --staged のほうがおすすめです。

GitHub Desktop ではチェックボックスがそのまま「ステージングするかどうか」を意味します。

  • チェックを 外す = ステージング解除
  • チェックを 付ける = ステージングに追加

これだけで切り替えできます。

ケースC: コミットを取り消したい

コミットしてしまった変更を取り消す方法は2つあります。

方法1: 直前のコミットをやり直す (履歴を作り変える)

git commit --amend

直前のコミット を上書きできます。コミットメッセージを書き間違えたとき、 ファイルを add し忘れたときなどに便利。

他人と共有済みのコミットを --amend で書き換えるのは混乱のもとです。 自分1人で使っているリポジトリだけで使いましょう。

方法2: 「打ち消しコミット」を作る (履歴は残す)

git revert <コミットID>

指定したコミットを 打ち消す新しいコミット を作ります。 履歴は残るので、共有済みのコミットでも安全に取り消せます。

GUI で revert する場合

  1. GitHub Desktop の「History」タブを開く
  2. 取り消したいコミットを右クリック
  3. 「Revert changes in commit」を選ぶ

覚えるべきは「困ったときの合言葉」

慣れないうちはこの一覧表を覚えるよりも、「困ったらまず git status」 の習慣をつけるほうが大切です。 status の表示には、必ず「次に何をすればいいか」のヒントが書いてあります。

このステップのまとめ

  • 編集だけ取り消し → git restore <ファイル>
  • ステージング取り消し → git restore --staged <ファイル>
  • 直前のコミットを直す → git commit --amend
  • 過去のコミットを打ち消す → git revert <ID>
