STEP 09

ブランチを作る

このステップのゴール

  • ブランチ が何のためにあるかを理解する
  • 新しいブランチを作れるようになる

ブランチって何のためにある？

ブランチ は「履歴の枝分かれ」を作る仕組みです。 たとえば、こんな場面で役立ちます。

  • 「ちょっと実験的に機能を追加してみたいけど、失敗したらすぐ戻したい」
  • 「メイン作業を中断して、緊急のバグ修正だけ先にやりたい」
  • 「2人で別々の機能を、お互いの邪魔をせずに開発したい」

ブランチを作ると、そのブランチでの変更は 他のブランチには影響しません。 気軽に試して、よければ後で マージ して取り込めばよく、ダメなら捨てればいいだけ。

main ブランチ

git init したリポジトリには、最初から main という名前のブランチがあります。 これは「本流」を意味する main ブランチ です。 普段の作業はここで行い、必要に応じて他のブランチを切って実験する、という使い方が一般的。

昔は master という名前が使われていました。今でも古いリポジトリでは見かけますが、新規には main が推奨されています。

新しいブランチを作る

ブランチを作るだけ

たとえば experiment という名前のブランチを作るには:

git branch experiment

これでブランチが作られます。ただし、まだそのブランチに移動はしていません。

ブランチ一覧を見る

git branch

こんな表示が出ます。

  experiment
* main

* がついているのが、いま自分がいるブランチです。

作成と移動を一度にやる (これがよく使われる)

git switch -c experiment

-c は「create」の略。ブランチを作って、すぐそのブランチに切り替える、という意味です。 実際の現場では、こちらを使うことが多いです。

古い書き方では git checkout -b experiment ですが、新しい git switch のほうがおすすめ。

GitHub Desktop でブランチを作る

  1. 上部の「Current branch」と書かれたボタンをクリック
  2. 「New branch」ボタンを押す
  3. ブランチ名を入力 (例: experiment)
  4. 「Create branch」をクリック

作成と同時に、自動でそのブランチに切り替わります。 現在のブランチは画面上部の「Current branch」欄に表示されているので、いつでも確認できます。

ブランチが作られた仕組み

ブランチを作った直後は、見た目には何も変わりません。hello.txt も同じ内容のままです。

しかしここで、新しいブランチで hello.txt に何か変更を加えてコミットしても、 main ブランチの hello.txt には影響しません。これがブランチの威力です。 

main:        コミット1 ── コミット2
                              \
experiment:                    新しいコミット (これは main には影響なし)

ブランチ名のつけかた

慣例として、ブランチ名は次のような形がよく使われます。

  • feature/login-form — 新機能の開発
  • fix/typo-on-top-page — バグ修正
  • experiment/try-new-design — 実験

/ や - を使うのは普通ですが、スペースや日本語は避けたほうが無難です。

このステップのまとめ

  • git switch -c <名前> で「ブランチを作って、そこに移動」できる
  • ブランチを切ると、本流 (main) を傷つけずに作業できる
  • GUI なら「Current branch」→「New branch」で作れる
