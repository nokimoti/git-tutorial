用語集

ハッシュ (Hash)

あるデータの中身から計算される、固定長の英数字の文字列。 その内容にだけ対応する「指紋」のようなもので、Git のあらゆる場所で使われています。

例で見るハッシュ

「hello」というたった5文字の中身を SHA-1 ハッシュにかけると、こうなります:

hello
↓ SHA-1
aaf4c61ddcc5e8a2dabede0f3b482cd9aea9434d

40文字の英数字。短い「hello」も、長い小説でも、結果は必ず40文字です。

ハッシュの3つの大事な性質

  1. 同じ内容 → 必ず同じハッシュ (世界中どこで計算しても同じ結果)
  2. 1文字でも違う → 全く違うハッシュ ("hello" と "Hello" は別のハッシュになる)
  3. ハッシュから内容は復元できない (一方通行の計算)

Git での使われ方

Git は オブジェクト (blob, tree, commit, tag) すべてをハッシュで識別します:

  • blob のID = ファイル内容のハッシュ
  • tree のID = フォルダ構造の情報のハッシュ
  • commit のID ( コミットID) = tree + 親 + メタ情報のハッシュ

なぜハッシュが便利?

  • 同じ内容は1度しか保存されない — 重複が自動で防げる (容量節約)
  • 改ざんを検出できる — 1ビットでも変えると ID が変わる
  • 世界中で同じ ID を共有できる — サーバが違っても同じ内容なら同じ ID

SHA-1 とは

Git が使っているハッシュ計算の方式の名前です ("Secure Hash Algorithm 1" の略)。 最近では SHA-256 への移行も進んでいますが、初心者がそれを意識する必要はほぼありません。

関連用語

  • コミットID — コミットのハッシュ
  • オブジェクト — ハッシュで管理される単位
