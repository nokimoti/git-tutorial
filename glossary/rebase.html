用語集

リベース (Rebase)

git rebase のこと。自分のブランチのコミット列を、別のブランチの最新コミットの上に「並べ直す」 操作。マージとは別の方法でブランチを統合します。

イメージ

変更前:
main:        A ── B ── C
                  \
feature:           D ── E

git rebase main (feature ブランチで実行)

変更後:
main:        A ── B ── C
                        \
feature:                 D'── E'   ← C の上に積み直された

マージとの違い

マージリベース
履歴の形枝分かれ・合流が残る1本の直線になる
マージコミット作られる作られない
コミットID変わらない新しくなる (D→D')
初心者向け○ 安全△ 注意点多い

使う場面

  • 機能ブランチを最新の main の上に追従させたい
  • コミット履歴をきれいな1本線に保ちたい
  • 複数のコミットをまとめたい (git rebase -i)

注意

リベースは コミットID を作り直す ため、共有済みのコミットでやると他人のリポジトリと不整合が起きます。 まだ push していない自分のローカルブランチだけ で使うのが鉄則。

関連用語

  • マージ — もう1つの統合方法
  • コミットID
