しくみ A6

実際に .git の中身を覗いてみる

このステップのゴール

  • これまで学んだ仕組みを 自分の手で確認 する
  • HEAD → branch → commit → tree → blob の連鎖を実際にたどる

準備

入門ステップで作った練習用リポジトリ (my-first-repo) があれば、それを使えます。なければ新しく作ってください: 

mkdir explore-git
cd explore-git
git init
echo "hello world" > hello.txt
git add hello.txt
git commit -m "最初のコミット"

① .git の中身を見る

ls .git

こんな構成が見えるはずです:

HEAD            config          description     hooks/
info/           objects/        refs/
  • HEAD — 現在のブランチを指すファイル
  • refs/ — ブランチ・タグの定義
  • objects/ — 全オブジェクトの保管庫
  • config — リポジトリ固有の設定

② HEAD を覗く

cat .git/HEAD

結果はこんな感じ:

ref: refs/heads/main

↑ これが「いま main ブランチを見ているよ」という宣言。

③ main ブランチを覗く

cat .git/refs/heads/main

結果は40文字のハッシュ1行:

f1e2d3c4b5a698765432abcdef1234567890abcd

↑ これがあなたが作った最初のコミットの ID。

④ コミットオブジェクトを覗く

ハッシュをコピーして、次のコマンドで中身を見てみます ( <ハッシュ> は実際の値に置き換え): 

git cat-file -t <ハッシュ>     # 種類を確認 → commit
git cat-file -p <ハッシュ>     # 中身を表示

こんな出力が出ます:

tree abcd1234567890...
author    Taro Yamada <taro@example.com> 1746789600 +0900
committer Taro Yamada <taro@example.com> 1746789600 +0900

最初のコミット

⑤ tree オブジェクトを覗く

上の出力にあった tree 行のハッシュをそのまま:

git cat-file -p <treeハッシュ>

こんな出力:

100644 blob ce0136250...    hello.txt

↑ ここで初めて ファイル名 が登場します。tree が「名前 → blob」の対応表だったことを実感できます。

⑥ blob を覗く

git cat-file -p <blobハッシュ>

結果:

hello world

↑ これがあなたが書いたファイルの中身そのもの。

⑦ ハッシュを自分で計算してみる

ファイルの中身が同じなら、ハッシュも同じになります:

echo "hello world" | git hash-object --stdin

ここで出るハッシュが ⑥ で見た blob ハッシュと一致するはず。「内容 = ハッシュ」 の関係が体感できます。

⑧ ブランチを作って参照ファイルを確認

git switch -c experiment
ls .git/refs/heads/

新しく experiment ファイルが増えているはず:

experiment      main
cat .git/refs/heads/experiment

main と同じハッシュが入っているはずです (まだ何もコミットしていないから)。

cat .git/HEAD

↑ ref: refs/heads/experiment に書き換わっているはず。HEAD ファイルの中身が変わっただけ、というのが実感できます。

謎が解けるリスト

仕組みを知ると、入門ステップの操作が腑に落ちます。

疑問解
なぜブランチ作成が一瞬?ファイルを1つ作るだけ ([A5](05-refs.html))
なぜブランチ切替で「ファイルが変わって見える」?HEAD ファイル書換 → 指すコミットの tree を取り出してWDに展開
なぜコミットメッセージ書き換えるとIDが変わる?コミットの内容全部をハッシュ化しているから ([A4](04-commit-object.html))
なぜ Git はオフラインで動く?すべてのオブジェクトと参照が .git/ 内に自己完結しているから
なぜ巨大なリポジトリでも履歴が軽い?変わらない blob/tree は再利用されるから ([A3](03-tree.html))

🎉 内部のしくみ完了!

お疲れさまでした。これで Git の内部構造の基礎は理解できたはず。 もっと深く知りたい人は git help glossary や、Pro Git book (git-scm.com/book/ja/v2) の Chapter 10「Git の内側」がおすすめです。
