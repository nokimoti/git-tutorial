しくみ A4

Commit — スナップショットの結び目

このステップのゴール

  • commit = 「ある時点の tree」へのポインタ + メタ情報
  • 親コミットへのリンクが連なって履歴になる、という構造を理解する

Commit オブジェクトの中身

コミット オブジェクトは、思っているほど派手なものではありません。 実際の中身は、たった数行のテキストです。 

$ git cat-file -p <コミットハッシュ>
tree   abcd1234...
parent ef012345...
author    Taro Yamada <taro@example.com> 1746789600 +0900
committer Taro Yamada <taro@example.com> 1746789600 +0900

最初のコミット

各行を読み解くと:

  • tree — このコミット時点の フォルダ全体のスナップショット ([A3](03-tree.html))
  • parent — 直前のコミットのハッシュ。これが履歴を作る
  • author / committer — 名前・メール・日時 (STEP 03 で設定したもの!)
  • 空行のあと、コミットメッセージ本文

「コミット」の正体

コミットとは、結局のところ
「tree への矢印 + 親コミットへの矢印 + 作者・日付・メッセージ」
が書かれただけの、小さなテキストオブジェクトです。

履歴は「親」を辿った結果

各コミットが parent 行で前のコミットを指しているので、 コミット → 親 → 親 → 親… と辿っていけば履歴がすべて見られます。 

[最新のコミット]
   parent → [前のコミット]
              parent → [もっと前のコミット]
                         parent → (続く...)

これが git log で表示される内容の正体です。

マージコミットには親が2つ

マージ でできるマージコミットには、parent 行が 2行 並びます。 

tree   ...
parent abc1234   ← 取り込み先のブランチ最新
parent def5678   ← 取り込んだブランチの最新
author ...
committer ...

ブランチ feature をマージ

コミットIDはどう決まる?

コミットの ID (ハッシュ) は、上の中身全部をまるごとハッシュ化したもの。だから:

  • tree が違う → コミットIDが違う
  • 親が違う → コミットIDが違う
  • 1秒ずれる → コミットIDが違う
  • コミットメッセージを書き換える → コミットIDが違う

git commit --amend で「直前のコミットを書き換える」と新しいコミットIDになる、というのはこの仕組みのため。

このステップのまとめ

  • コミット = tree 参照 + 親コミット参照 + メタ情報
  • 親リンクが連なって履歴になる
  • マージコミットは親が2つ
  • 中身が1ビットでも違えばIDも違う
