しくみ A2

Blob — ファイルの中身が「裸」で保存される

このステップのゴール

  • blob = ファイル内容そのもの、と理解する
  • ファイル名は blob には含まれない という事実に驚く
  • 同じ内容のファイルが2つあっても、保存される blob は1つだけと知る

Blob とは

blob (ブロブ。"Binary Large OBject" の略) は、Git が保存する オブジェクト 4 種類の中で一番下の階層。 つまり ファイルの中身そのもの を表します。

意外な事実: blob にファイル名は入っていない

blob が保存しているのは 「内容」だけ。hello.txt という名前も、フォルダの場所も、blob 単体には記録されません。

ファイル名と blob を紐づけるのは、次のステップで学ぶ tree の仕事です。

Blob のIDは「内容の ハッシュ」

blob のIDは、その 内容を SHA-1 という方式でハッシュにかけた もの。 たとえば「hello」というたった1単語の中身なら、いつ・誰が・どこで保存しても、必ず同じハッシュになります。

「ハッシュ化」のおさらい: 内容から計算される 40 文字の英数字。中身が同じなら同じハッシュ、1ビットでも違えば全く違うハッシュになる「指紋」のようなもの。 → ハッシュ ページに詳しい解説あり。 
$ echo "hello" | git hash-object --stdin
ce013625030ba8dba906f756967f9e9ca394464a

この ce0136... がそのまま blob のID。同じ内容のファイルが2つあっても 同じID になるので、Git は1つしか保存しません (これを「重複排除」と呼びます)。

ファイルの中身を確認するコマンド

新しいコマンドが2つ登場します。

  • git hash-object — 内容からハッシュを計算するだけのコマンド
  • git cat-file — ハッシュを指定して、保存されているオブジェクトを取り出すコマンド (-p=中身を表示、-t=種類を表示)
# 既存ファイルから blob のハッシュを計算
git hash-object hello.txt

# 既に保存されている blob の中身を取り出す
git cat-file -p <ハッシュ>

# オブジェクトの種類を確認
git cat-file -t <ハッシュ>     # → blob

どこに保存される?

blob は .git/objects/ の中に格納されます。ハッシュの先頭2文字でフォルダ分けされる仕組み: 

ハッシュ: ce013625030ba8dba906f756967f9e9ca394464a
保存先 : .git/objects/ce/013625030ba8dba906f756967f9e9ca394464a

ファイル数が多くなるとフォルダ1つに集中しすぎるのを防ぐ工夫です。

このステップのまとめ

  • blob = ファイル内容そのもの (名前は含まない)
  • IDは内容のハッシュ → 同じ内容なら同じID → 重複しない
  • git hash-object でハッシュを計算、git cat-file -p で中身を読む
