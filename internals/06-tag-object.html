しくみ A6

注釈付きタグの内部 — 4つ目の オブジェクト

このステップのゴール

  • 軽量タグと注釈付きタグが 内部で全く違うしくみ で実装されていることを知る
  • 「タグオブジェクト」という4つ目のオブジェクトの中身を理解する
  • 2層構造 (ref → タグオブジェクト → コミット) のメリットが分かる

おさらい: 2種類のタグ

STEP 13 や A5 でも触れたように、タグ には2種類あります。

軽量タグ注釈付きタグ
作成git tag v1.0.0git tag -a v1.0.0 -m "..."
作者・日時記録されない記録される
メッセージ持てない持てる
署名 (GPG)不可可能
用途個人的な目印公開リリース

軽量タグの内部 (おさらい)

軽量タグは オブジェクト を作りません。ブランチ と全く同じく、1行のテキストファイル でしかありません。 

$ git tag v1.0.0-light                  # 軽量タグを作成

$ ls .git/refs/tags/
v1.0.0-light

$ cat .git/refs/tags/v1.0.0-light
f1e2d3c4b5a698765432abcdef1234567890abcd   ← コミットのハッシュ1行のみ

つまり「軽量タグ = ブランチを動かなくしたもの」と言えます。

注釈付きタグの内部 — ここが本題

注釈付きタグは 2層構造 です。図にするとこうなります: 

.git/refs/tags/v1.0.0  ──→  タグオブジェクト  ──→  コミット
   (ref ファイル)            (4種類目の object)      (commit object)
   "abc1234..."              tagger / message など       tree / parent など

ref ファイルが直接コミットを指す軽量タグと違って、間に タグオブジェクト が挟まっています。

タグオブジェクトとは

タグオブジェクトは、Git の オブジェクト 4種類のうちの最後の1つ (blob/tree/commit/tag)。 他のオブジェクトと同じく、ハッシュで識別され、.git/objects/ に保管されます。

タグオブジェクトの中身

実際の中身を覗くと、こんな構造です:

$ git cat-file -p <タグオブジェクトのハッシュ>
object f1e2d3c4b5a698765432abcdef1234567890abcd
type   commit
tag    v1.0.0
tagger Taro Yamada <taro@example.com> 1746789600 +0900

最初の正式リリース版です。
新機能Aと改善点Bを含みます。

各行の意味:

  • object — このタグが指す対象の ハッシュ (普通はコミット)
  • type — 指す対象の種類 (commit / tree / blob / tag のいずれか。99% は commit)
  • tag — タグの名前 (例: v1.0.0)
  • tagger — 作成者と日時 (コミットの author に相当)
  • 空行のあと、タグメッセージ本文
コミットオブジェクトの構造 (A4) とそっくりですね。違いは:
  • コミット: tree + parent + author/committer を持つ
  • タグ: object + type + tag + tagger を持つ

2層構造になっている本当の理由

「なぜ ref ファイルが直接コミットを指さず、わざわざタグオブジェクトを挟むのか?」

答え: タグ自身にメタ情報を持たせるため です。

  • 軽量タグは「ハッシュ1行」しか書けない → 作者も日時もメッセージも持てない
  • タグオブジェクトを挟めば、ref には タグオブジェクトのハッシュ を書くだけで、メタ情報はオブジェクト側に格納できる
  • タグオブジェクト自身が ハッシュ で識別される → タグの内容も改ざん検出できる
  • GPG で 署名 もタグオブジェクト内に埋め込める

実際に作って見比べる

練習用リポジトリ (なければ A7 冒頭の手順で1つ作る) で次を試してみてください。

① 両方のタグを作る

# 軽量タグ
git tag v1-light

# 注釈付きタグ
git tag -a v1-annot -m "正式リリース v1"

② ref ファイルの中身を比較

$ cat .git/refs/tags/v1-light
f1e2d3c4...                 ← コミットのハッシュ

$ cat .git/refs/tags/v1-annot
abcd9876...                 ← タグオブジェクトのハッシュ (コミットのではない!)

違いはここ。 軽量タグの ref はコミットを直接指しているのに対し、注釈付きタグの ref は タグオブジェクトを指している。

③ それぞれのオブジェクトの種類を確認

$ git cat-file -t f1e2d3c4...        # 軽量タグの先
commit                                ← コミットだ

$ git cat-file -t abcd9876...        # 注釈付きタグの先
tag                                   ← タグオブジェクトだ!

tag という種類が出れば、それが 4つ目のオブジェクト の正体です。

④ タグオブジェクトの中身を表示

$ git cat-file -p abcd9876...
object f1e2d3c4...
type   commit
tag    v1-annot
tagger Taro Yamada <taro@example.com> 1746789600 +0900

正式リリース v1

git show すると同じに見える、その理由

git show v1-light も git show v1-annot も、画面に出てくるのはほぼ同じコミット情報です。 これは Git が裏で タグオブジェクトを「素通り」して、その先のコミットまで自動で辿ってくれる から。 内部構造が違っていても、ユーザー目線ではほぼ同じに使えるよう設計されているわけです。

GPG 署名タグ (発展)

git tag -s v1.0.0 -m "..." で GPG 署名付きタグを作れます。 タグオブジェクトの末尾に署名ブロックが追加され、後から git tag -v v1.0.0 で 「本当に作者本人が作ったタグか」 を検証できます。 

object f1e2d3c4...
type   commit
tag    v1.0.0
tagger ...

正式リリース
-----BEGIN PGP SIGNATURE-----
iQGzBAABCAAdFiEEXXXXXX...
...
-----END PGP SIGNATURE-----

OSS のリリースタグでよく見かけます。署名はタグオブジェクトのハッシュにも反映されるので、改ざんは即バレです。

まとめ: 全体像

軽量タグ
  .git/refs/tags/v1-light  ──→  commit object

注釈付きタグ
  .git/refs/tags/v1-annot  ──→  tag object  ──→  commit object
                                 (object=…)
                                 (tag=v1-annot)
                                 (tagger=…)
                                 (message)
                                 (signature?)

このステップのまとめ

  • 軽量タグ = ブランチ同様のただの ref ファイル
  • 注釈付きタグ = ref + タグオブジェクト (4種類目のオブジェクト) の2層構造
  • タグオブジェクトはメタ情報・メッセージ・署名を持てる独立した存在
  • タグオブジェクト自身もハッシュで保護される → 改ざん検出可能
