しくみ A3

Tree — フォルダ構造を表す目録

このステップのゴール

  • tree = フォルダのスナップショット、と理解する
  • tree が ファイル名 と blobのハッシュ を結びつけることを知る
  • サブフォルダは「tree が tree を参照する」入れ子で表現される

Tree とは

tree (ツリー) は、ある時点のフォルダ1つ分のスナップショット (= その瞬間のフォルダの中身を写した記録) を表す オブジェクト です。 内容はとてもシンプルで、「ファイル名 + そのファイルの blob ハッシュ」のリスト でしかありません。

Tree の中身を見る

たとえばこんなファイル構成があったとします。

my-project/
├── hello.txt
├── README.md
└── src/
    └── main.py

これに対応する tree オブジェクトの中身は次のような形です。

$ git cat-file -p <ルートtreeのハッシュ>
100644 blob ce0136...    hello.txt
100644 blob 3b18e5...    README.md
040000 tree 8f2a91...    src

各行を読み解くと:

  • 100644 — ファイルのモード (= 種類と権限を表す数字)
  • blob または tree — オブジェクト の種類
  • ハッシュ — そのオブジェクトのID
  • 名前 — ファイル名 / フォルダ名
「モード」の数字って何? Unix 系 OS で使われる、ファイルの種類と読み書き権限を表す8進数表記です。Git でよく出るのはこの3つだけ:
  • 100644 — 普通のファイル
  • 100755 — 実行可能ファイル (スクリプトなど)
  • 040000 — フォルダ (= サブの tree)
暗記する必要はありません。「100... ならファイル、040... ならフォルダ」だけ覚えれば大丈夫。

サブフォルダ = 別の tree

src 行に注目してください。tree 種別で、ハッシュ 8f2a91... の別の tree を指しています。

つまり src/ の中身は、別の tree オブジェクトに丸投げされている形:

$ git cat-file -p 8f2a91...
100644 blob 7d4ee2...    main.py

フォルダ階層は、このように 「tree が tree を参照する入れ子構造」 で表現されます。

blob と tree の関係

[ルートtree]
   ├─ "hello.txt"  ──→ [blob: ce0136...]
   ├─ "README.md"  ──→ [blob: 3b18e5...]
   └─ "src" ────→ [tree: 8f2a91...]
                    └─ "main.py" ──→ [blob: 7d4ee2...]

ファイル名は tree 側に存在し、blob は中身だけを持つ。役割がきれいに分かれています。

同じフォルダ構造は同じ tree

tree 自体もハッシュで識別されるので、中身が同じフォルダは同じ tree になります。 たとえば「2つのコミットの間で src/ が一切変わっていない」場合、両方のコミットが同じ src tree を再利用します。

これが Git が容量効率に優れる理由のひとつ。コミットを重ねても、変わってないファイル/フォルダは再利用されるので、無駄なデータが増えません。

このステップのまとめ

  • tree = フォルダ1つ分のスナップショット
  • 「ファイル名 + blobハッシュ」のリストを持つ
  • サブフォルダは「tree が tree を参照」する入れ子で表現
  • 変わらない部分は再利用される (容量節約)
